El servicio y la entidad

una clase que guarda y modifica tareas

Click derecho sobre el proyecto LabBlazor → Add → Class/Interface, nombre TareaServicio. Reemplazá todo el contenido por esto. No hay nada que completar: es el servicio ya armado.

namespace LabBlazor;

public class Tarea
{
    public int Id { get; set; }
    public string Titulo { get; set; } = "";
}

public class TareaServicio
{
    private readonly List<Tarea> _tareas = new();
    private int _proximoId = 1;

    // Un código corto para reconocer cuál instancia del servicio estás usando.
    public string IdInstancia { get; } = Guid.NewGuid().ToString("N")[..6];

    public IReadOnlyList<Tarea> Listar() => _tareas;

    public void Agregar(string titulo)
    {
        _tareas.Add(new Tarea { Id = _proximoId++, Titulo = titulo });
    }

    public void Quitar(int id)
    {
        _tareas.RemoveAll(t => t.Id == id);
    }

    public void Editar(int id, string nuevoTitulo)
    {
        var tarea = _tareas.FirstOrDefault(t => t.Id == id);
        if (tarea is not null) tarea.Titulo = nuevoTitulo;
    }
}

Fijate en tres cosas, porque las vamos a usar durante todo el ejercicio:

  • Tarea es la entidad: tiene un Id y un Titulo.
  • TareaServicio guarda la lista en memoria y sabe Listar, Agregar, Quitar y Editar.
  • IdInstancia es un código al azar que se genera una sola vez, cuando se crea el objeto. Sirve para reconocer qué instancia del servicio estamos usando.

Compilá desde la terminal de Rider:

dotnet build   # tiene que terminar en "Build succeeded."
CheckpointLa compilación termina en Build succeeded. sin errores.

Registrar, inyectar y conectar

Program.cs + @inject + CRUD en pantalla

Regla de oroCada vez que toques Program.cs: ■ Stop y después ▶ Run. Con la app corriendo el cambio parece guardado, pero no se aplica: sigue funcionando la versión vieja y no da ningún error. Rider tiene una opción para que los cambios se actualicen sin reiniciar (se llama Hot Reload), pero buscarla queda por cuenta de cada uno. En este ejercicio, siempre Stop y Run.

3A · Registrar el servicio. Program.cs es el archivo donde se configuran los servicios de la aplicación: ahí le decimos al contenedor de inyección de dependencias qué servicios existen y con qué «vida» (Scoped o Singleton). Después, cada página los pide con @inject, que es lo que vas a hacer en 3B.

Abrí Program.cs y completá el TODO 2. El contenedor se arma en Build(), así que la línea tiene que quedar antes:

using LabBlazor;

var builder = WebApplication.CreateBuilder(args);

// ... acá quedan las líneas que ya traía la plantilla ...

// TODO 2: registrar TareaServicio en el contenedor con vida Scoped

var app = builder.Build();   // <- todo lo de arriba tiene que ir ANTES de esta línea
PistaUn servicio se registra con una línea de este estilo: builder.Services.AddScoped<MiClase>();. El nombre del método elige la vida del servicio (AddScoped, AddSingleton o AddTransient) y entre los signos <> va el nombre de la clase que querés registrar.

3B · Inyectar y conectar la página. Reemplazá todo el contenido de Tareas.razor por esto. Rider va a marcar en rojo Servicio hasta que resuelvas el TODO 3:

@page "/tareas"
@rendermode InteractiveServer
@* TODO 3: inyectá acá el servicio (tipo TareaServicio, nombre Servicio) *@

<PageTitle>Tareas</PageTitle>

<h1>Mis tareas</h1>

<p>
    Instancia del servicio:
    <strong>@(RendererInfo.IsInteractive ? Servicio.IdInstancia : "conectando…")</strong>
</p>

<input class="form-control mb-2" @bind="texto" @bind:event="oninput" placeholder="Título de la tarea" />
<button class="btn btn-primary mb-3" @onclick="Guardar">@(editandoId is null ? "Agregar" : "Guardar cambios")</button>

<ul>
    @foreach (var t in Servicio.Listar())
    {
        <li>
            @t.Titulo
            <button class="btn btn-sm btn-outline-secondary" @onclick="() => Editar(t)">Editar</button>
            <button class="btn btn-sm btn-outline-danger" @onclick="() => Quitar(t.Id)">Quitar</button>
        </li>
    }
</ul>

PistaPara inyectar un servicio en una página se escribe una sola línea con este esquema: @inject TipoDelServicio NombreQueElijas. Primero va el tipo (la clase del servicio) y después el nombre con el que lo vas a usar en el resto de la página: fijate cuál aparece en el código de arriba.
