0B · El servicio y la entidad. Click derecho al proyecto LabBlazor(el de arriba) Add → New Project → Class Library, nombre Servicios, y renombra Class1 a TareaServicio. Reemplazá todo el contenido por esto. No hay nada que completar, y no se le pide nada a la IA, es una simplificacion dominio/servicio ya armado.

namespace LabBlazor.Servicios;

public class Tarea
{
    public int Id { get; set; }
    public string Titulo { get; set; } = "";
}

public class TareaServicio
{
    private readonly List<Tarea> _tareas = new();
    private int _proximoId = 1;

    // Un código corto para reconocer cuál instancia del servicio estás usando.
    public string IdInstancia { get; } = Guid.NewGuid().ToString("N")[..6];

    public IReadOnlyList<Tarea> Listar() => _tareas;

    public void Agregar(string titulo)
    {
        _tareas.Add(new Tarea { Id = _proximoId++, Titulo = titulo });
    }

    public void Quitar(int id)
    {
        _tareas.RemoveAll(t => t.Id == id);
    }

    public void Editar(int id, string nuevoTitulo)
    {
        var tarea = _tareas.FirstOrDefault(t => t.Id == id);
        if (tarea is not null) tarea.Titulo = nuevoTitulo;
    }
}

Fijate en cuatro cosas, porque son las que vas a necesitar para escribir el prompt del paso 5:

  • Tarea es la entidad: tiene un Id y un Titulo.
  • TareaServicio guarda la lista en memoria y sabe Listar, Agregar, Quitar y Editar. Cuatro métodos, y ni uno más.
  • Cada método tiene su firma: Agregar recibe un string y devuelve nada; Editar recibe un int y un string; Quitar recibe un int.
  • IdInstancia es un código al azar que se genera una sola vez, cuando se crea el objeto. Sirve para reconocer qué instancia del servicio estamos usando.

Como el servicio quedó en otro proyecto, LabBlazor todavía no lo puede ver. Click derecho sobre el proyecto LabBlazor → Add → Reference… → marcá Servicios → OK. Sin esa referencia, el paso 4 no compila.

Las tres piezas de una página

3 min

contexto antes de promptear

Una página Blazor siempre tiene las mismas tres piezas. Este es un ejemplo completo, para tener algo a qué mirar mientras las describimos:

Las tres, una por una:

  • El markup: HTML con cosas de C# metidas adentro. Es lo que se ve. Empieza con @page "/ruta".
  • El @code: un bloque de C# con las variables y los métodos de la página. Es la lógica.
  • El @inject: la línea que le pide al framework una instancia de un servicio. Es el puente hacia el resto de la aplicación.

Y por afuera de todo eso hay dos archivos que vamos a tocar:

  • Program.cs: donde se configuran los servicios. Ahí se decide si un servicio es Scoped, Singleton o Transient.
  • NavMenu.razor: el menú lateral, donde se selecciona a que pagina ir con un NavLink por página.
Recordamos
  • Singleton: una única instancia durante toda la aplicación.
  • Scoped: una instancia por cada solicitud del cliente.
  • Transient: una nueva instancia cada vez que se solicita.
Una página Blazor no sabe si la instancia del servicio que recibe es Singleton, Scoped o Transient. Eso está definido en Program.cs.

Luego en el Blazor la linea @inject indica qué servicio necesita y recibe su instancia mediante la inyección de dependencias..
CheckpointPudés explicar de memoria qué archivo decide el ciclo de vida del servicio y donde se recibe la instancia.

Del boceto al markup

8 min

Razor + Bootstrap, sin lógica

Ahora sí, el código. Este prompt es deliberadamente estrecho: le pide solamente el HTML/Razor, y le prohíbe explícitamente el @code. La idea es no mezclar las dos cosas: el @code va a salir de un prompt distinto, en el paso 5, con toda la información del servicio.

Abrí una conversación nueva, pegá el boceto que generaste en el paso 2 y mandale este prompt:

Actúa como un desarrollador frontend experto en Blazor Server, Razor y Bootstrap.
A partir del boceto de referencia, generá el código markup de Blazor necesario para representar la interfaz.

Funciones y variables disponibles (usalas tal cual en los bind y eventos):
-Servicio: Servicio (instancia de TareaServicio)
-Lista de tareas: Servicio.Listar()  → cada tarea t tiene t.Id (int) y t.Titulo (string)
-Código de instancia: Servicio.IdInstancia (string)
-Campo de texto: texto  → @bind="texto" @bind:event="oninput"
-Acciones:
Agregar() → @onclick="Agregar"
Quitar(int id) → @onclick="() => Quitar(t.Id)"
Editar(int id, string nuevoTitulo) → @onclick="() => Editar(t.Id, textoEdicion)"
-Si el boceto muestra otros elementos que no están en esta lista, no les agregues lógica: dejalos solo como HTML.

Requisitos:
-Respetá lo más fielmente posible el diseño y la distribución del boceto.
-Usá Bootstrap y las clases CSS reutilizables.
-Generá código limpio, ordenado y responsive.
-Usá los nombres de variables y métodos de la lista de arriba, sin renombrarlos.
-Recorré las tareas con @foreach y usá t.Id para identificar cada una en las acciones.

-No generes métodos, variables ni propiedades C#.

IMPORTANTE:
Devolvé ÚNICAMENTE el código markup de Blazor, listo para pegar en un archivo .razor.
NO incluyas @code, @inject, directivas @page, CSS, JavaScript, explicaciones ni bloques Markdown.

El @code con IA

8 min

la lógica de la página

Último prompt. Este es el más delicado de los tres, porque acá la IA tiene que saber cosas que no puede inventar: cómo se llama tu servicio, qué métodos tiene y qué recibe cada uno. Por eso el prompt no dice «hacé un formulario»: dice este es mi servicio, con estos métodos, armá el @code con esta estructura.

Antes de mandarlo, reemplazá todos los [ejemplo: …] (marcados en amarillo) por lo de tu proyecto. Si tu servicio tiene métodos distintos, adaptalos: lo que no puede hacer la IA es adivinar.

Actúa como un desarrollador Blazor Server que trabaja en arquitectura de capas.
Generá el bloque @code para este formulario siguiendo el patrón mostrado.

Ya tenés inyectado el servicio, así que NO lo declares:
 [ejemplo: @inject TareaServicio Servicio]

Este es el servicio y sus métodos exactos, no inventes otros:
 [ejemplo: Listar() devuelve IReadOnlyList · Agregar(string titulo) · Editar(int id, string nuevoTitulo) · Quitar(int id) · IdInstancia]

ESTRUCTURA:
1. Propiedades de datos:
   [ejemplo: private IEnumerable tareas;]
   [ejemplo: private string texto = "";]
2. Propiedades de control:
   [ejemplo: private int? editandoId;]
   [ejemplo: private string mensaje = "";]
   [ejemplo: private string error = "";]
3. Ciclo de vida:
   - OnInitialized(): Carga los datos del servicio
4. Métodos principales (uno por acción):
   - Guardar(): Crea una tarea nueva o guarda los cambios, según corresponda
   - Editar(tarea): Prepara la edición
   - Quitar(id): Elimina
5. Método Guardar() con try-catch:
   - Llama al servicio según el caso
   - Maneja excepciones
   - Actualiza mensajes
   - Limpia formulario
6. Métodos auxiliares:
   - Cargar(): Recarga los datos del servicio
   - ClearMessages(): Limpia los mensajes
IMPORTANTE:
-Try-catch en las operaciones que lo requieran.
-Devolvé ÚNICAMENTE el bloque @code, listo para pegar dentro del archivo .razor.
-NO incluyas directivas @page, @inject ni @using, porque ya están escritas.
-No generes métodos, variables ni propiedades C# que no estén en la estructura de arriba.

La respuesta debería verse así (o muy parecida):

@code {
    // 1. Propiedades de datos
    private IEnumerable<Tarea> tareas = Enumerable.Empty<Tarea>();
    private string texto = "";

    // 2. Propiedades de control
    private int? editandoId;
    private string mensaje = "";
    private string error = "";

    // 3. Ciclo de vida
    protected override void OnInitialized()
    {
        Cargar();
    }

    // 4. Métodos principales
    private void Guardar()
    {
        try
        {
            if (string.IsNullOrWhiteSpace(texto)) return;

            if (editandoId is null)
            {
                Servicio.Agregar(texto);
                mensaje = "Tarea agregada.";
            }
            else
            {
                Servicio.Editar(editandoId.Value, texto);
                mensaje = "Tarea actualizada.";
            }

            texto = "";
            editandoId = null;
            Cargar();
        }
        catch (Exception ex)
        {
            error = ex.Message;
        }
    }

    private void Editar(Tarea t)
    {
        editandoId = t.Id;
        texto = t.Titulo;
        ClearMessages();
    }

    private void Quitar(int id)
    {
        try
        {
            Servicio.Quitar(id);
            Cargar();
        }
        catch (Exception ex)
        {
            error = ex.Message;
        }
    }

    // 5. Métodos auxiliares
    private void Cargar()
    {
        tareas = Servicio.Listar();
    }

    private void ClearMessages()
    {
        mensaje = "";
        error = "";
    }
}
Revisá antes de pegarUna IA genera código que parece correcto y no lo es. En este paso, mirá estas cuatro cosas:
  • ¿Llama a métodos que existen en TareaServicio con la misma entrada? Si inventó Obtener() o Borrar(), no compila: corregilo vos.
  • ¿Repetí la declaración @inject? Vos ya la escribiste en el paso 4; si la pegás dos veces, Blazor se queja.
  • ¿Los nombres de las propiedades coinciden con los del markup del paso 3 (tareas, texto, editandoId, mensaje, error)? Si la IA le puso otros, el markup se rompe.
  • ¿En el markup y el @code usan la misma lista de Tareas?
  • ¿Compila? Este es el único punto del recorrido donde por fin se puede correr la app. Si al correr salta un error de compilación, volvé a leer los tres puntos de arriba.
